# 站内 AI 问答 · 方案规划

> 目标：在「烯烃复分解」学术展示站里放一个抽屉式问答助手。
> 硬约束：**只能基于站内内容回答**，不得使用模型自身知识、不得联网检索；
> 命中时回答并跳转到对应章节；问题与回答可存储。

---

## 1. 三条硬约束怎么落地

「不许用模型知识」这句话，靠提示词是保证不了的。所以拆成**三道闸**，任何一道拦住都不会产生外部知识：

| 闸 | 位置 | 作用 | 失效时 |
|---|---|---|---|
| ① 检索门控 | 浏览器，调用模型之前 | 站内文本检索不到「实词重叠」就直接不调用模型 | 不花 token，直接回「站内暂无相关内容」 |
| ② 提示词约束 | 请求体 system 消息 | 限定只能用 `<站内资料>`、必须标 `[来源 N]`、资料不足就说没有 | 模型越界时最多是措辞问题，事实仍来自片段 |
| ③ 无工具 | 请求参数 | 不给模型任何 tools / function call / 联网能力 | 结构上没有外泄通道 |

此外还有一道**物理**边界：本站是纯静态托管，没有后端、没有数据库、没有联网中间件。
模型拿到的只有我拼进去的那几个片段。

## 2. 架构

```
浏览器                                     DeepSeek
┌──────────────────────────────┐
│ site/index.html（预渲染）      │
│  ├─ app.js   页面与搜索        │
│  ├─ search.js  BM25（共用）    │
│  └─ ai.js    抽屉              │
│        │                       │
│        ├─ data/rag-index.json ─┘ 81 个片段（阶段/文献/图/缺口/方法）
│        │  本地检索 → 取 top-5
│        ├─ 门控判定 ── 未命中 ─→ 直接回「站内暂无相关内容」
│        └─ 命中 → fetch ────────────→ POST /chat/completions
│                             ←──────  SSE 流式返回
└──────────────────────────────┘
```

**为什么不用向量检索**：81 个片段、中文短查询、领域词密集（Grubbs、Z-选择性、BILN 2061）。
BM25 + 中文二元切分在这个规模上召回足够，且**零依赖、零构建、可离线跑**，
不会因为 embedding API 不可用而整站问答失效。规模上到几千片段再换混合检索。

**为什么不用后端**：GitHub Pages 是静态托管，加后端就要另找服务器。
Key 由使用者自己填、存本地、直连 DeepSeek（已验证 `api.deepseek.com` 支持浏览器跨域），
这样既不用把 Key 写进仓库，也不需要运维。

## 3. 检索层

### 3.1 片段（chunk）设计

| 类型 | 数量 | 内容 | 锚点 |
|---|---|---|---|
| overview | 1 | 全站摘要 | `#top` |
| phase | 5 | 时期 + 名称 + 导语 + 4 条核心进展 + 一句话概括 | `#phase-p1…p5` |
| paper | 45 | 作者、标题、刊名卷页、DOI、为什么重要、所属阶段 | `#paper-P01…P45` |
| figure | 23 | 图号、图注、原文页码、章节、用法说明 | `#fig-<id>` |
| gap | 5 | 四个缺口 + 总结 | `#gaps` |
| catalyst / method | 2 | 谱系总述、方法与边界 | `#catalysts` `#method` |

每个片段都是**自足**的：单独拿出来也能读懂，因为要直接喂给模型。

### 3.2 分词

中文没有空格，用「单字 + 二元组」：

```
"Z-选择性"  →  归一 "z选择性"  →  去功能词  →  z + 选/择/性 + 选泽?  →  选择, 择性
```

- 英文/数字按词切（`grubbs`、`biln`、`2061`）；
- 去停用短语（为什么 / 是什么 / 怎么样 / 如何 / 哪些 / 谁 / 一下 …）与语气字（的 / 了 / 吗 / 呢）；
- 去连字符，让「Z-选择性」与「Z选择性」等价。

### 3.3 打分

BM25（k1=1.4, b=0.72）＋ 三项修正：

1. **字段权重**：标题 ×3、关键词字段 ×1.4、正文 ×1；
2. **类型先验**：阶段 +0.9、缺口 +0.7、综述性 +0.5、图 +0.15（阶段与缺口更像「答案」）；
3. **排序加罚**：`score + 2 × 命中实词数`，避免长片段靠词频堆分。

### 3.4 门控（关键）

只看分数会被噪声骗到——「今天天气怎么样」在语料里也能匹配到「天」「气」。所以门控看的是**有没有真正的实词重叠**：

```
命中实词数 = 匹配到的 ≥2 字词（中文二元组 / 英文单词）的个数

通过条件：命中实词数 ≥ 1  且  (实词数 ≥ 2  或  最高分 ≥ 6)
否则：判为未命中，不调用模型
```

实测（`window.__ai.retrieve()`，7 条探针）：

| 提问 | 判定 | 首位命中 |
|---|---|---|
| Chauvin 的机理为什么难验证？ | ✅ | 1955–1978 现象 → 机理之争（s=16.3, 实词 2） |
| 文档给的文献缺了什么？ | ✅ | 文献缺口 01：零原始文献（s=30.8, 实词 3） |
| Grubbs Ⅰ 代和 Ⅱ 代差在哪？ | ✅ | 图 2 一代/二代 Ru 催化剂（s=7.7） |
| Z-选择性是什么时候做出来的？ | ✅ | 2011–2024 选择性时代（s=22.0, 实词 3） |
| 哪张图和索烃有关？ | ✅ | 图 4 索烃的生成（s=21.0） |
| 今天天气怎么样？ | ❌ 无实词 | 不调用模型 |
| 如何做红烧肉？ | ❌ 无实词 | 不调用模型 |

## 4. 提示词

system 消息（原文见 `site/assets/ai.js` 的 `SYSTEM_PROMPT`），7 条硬性规则：

1. 只能依据 `<站内资料>`；禁止训练知识、常识补全、联网信息；
2. 资料不足只回「站内暂无相关内容。」，可建议 1–2 个站内关键词；
3. 每个论断后标 `[来源 N]`；没有资料支撑的句子不要写；
4. 不得编造/改写作者、年份、卷页、DOI、产率等任何数字；
5. 简体中文，先结论后 2–4 条依据，≤220 字；
6. 不出现「根据资料」「作为 AI」「我无法」这类话术；
7. 与站内主题无关，直接回「站内暂无相关内容。」

user 消息把 top-5 片段按 `[来源 N] 标题（锚点：#…）` 拼进 `<站内资料>`，末尾接问题。

请求参数：`temperature: 0.1`、`stream: true`、`max_tokens: 700`，**不带 tools**。

## 5. 命中即跳转

命中后立刻（**在回答开始之前**）把页面滚到首位命中的锚点：

- 抽屉在右侧 480px，左侧正文仍然可见，所以用户能同时看到「文字被跳到了哪」；
- 回答里每个 `[来源 N]` 都是可点按钮，点了再跳；
- 回答下方列出全部 5 个来源按钮，可逐个翻；
- 设置里可关掉自动跳转（`autoJump`）。

跳转复用 `window.Jump(anchor)`：计算 header 高度、`scrollTo`、给目标加 1.6s 高亮闪烁。

## 6. 存储

只存本机（`localStorage`），不上传、不共享：

| Key | 内容 | 上限 |
|---|---|---|
| `om.ai.settings.v1` | `{apiKey, model, endpoint, autoJump}` | 单条 |
| `om.ai.history.v1` | `[{id, q, a, sources[], ts}]` | 120 条（FIFO） |

- 写入时机：回答流式结束（或未命中时立即写入），避免半截答案入库；
- 回看：`☰` 面板列出问题与时间，点击重放到对话区并恢复来源按钮；
- 单条删除 / 全部清空 / 导出 JSON（带 `exportedAt` 与站点标识，便于归档）；
- 隐私：Key 与历史都只在本机；换浏览器或清缓存即丢失。
- 配额：localStorage 约 5 MB，120 条 × 平均 300 字 ≈ 200 KB，远未触顶；写入失败会 `console.warn` 而不是静默。

## 7. 失败与降级

| 情况 | 表现 |
|---|---|
| 没填 Key | 抽屉里提示去 ⚙ 填写；不发起请求 |
| 401 | 「API Key 无效或已过期」 |
| 402 | 「账户余额不足」 |
| 429 | 「请求太频繁或额度用尽」 |
| 网络失败 / 被拦截 | 提示可能是接口地址或代理的跨域问题，可在 ⚙ 换地址 |
| 浏览器不支持流式 | 自动退回整体 JSON 解析 |
| 索引加载失败 | 提示需通过 HTTP 访问（双击 HTML 会被 `fetch` 拦截） |
| 未命中 | 明确说站内没有，并给 3 个可能相关的锚点 |

## 8. 安全

- **Key 不落仓库**：只存在使用者浏览器的 localStorage；仓库里没有任何密钥。
- **可选代理**：若单位网络直连不通，可在 ⚙ 把接口地址改成自建代理（Cloudflare Worker 十行即可），
  代理侧再加一层站点白名单即可；本站不内置代理。
- **XSS**：模型输出先 `esc()` 转义再渲染，`[来源 N]` 用白名单正则替换成按钮，不注入 HTML。
- **提示注入**：站内片段是我自己生成的白名单文本，不含用户可写内容；模型无工具，注入面很小。

## 9. 后续可做

1. **混合检索**：加一层向量召回（本地 `transformers.js` 或预计算 embedding），处理同义改写；
2. **答案缓存**：同一问题命中同一组片段时直接回放，省 token；
3. **服务端代理**：若要多用户共享配额，加一个最小 Worker，做限流与日志；
4. **审计面板**：把「未命中」的提问收集起来，反推网站的覆盖盲区；
5. **引用高亮**：回答滚动到对应段落时，把对应句子在正文里高亮。
